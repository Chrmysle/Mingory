# Mingory

家庭日杂店轻量级进销存微信小程序。当前已实现 `开发文档.md` 定义的 Phase 1～Phase 6：

- 微信云开发初始化；
- 微信身份识别与 `users` 白名单校验；
- `users`、`products` 最终字段模型；
- 云函数调用层与金额（整数分）工具。
- 商品新增、编辑、详情、分页列表和搜索；
- 服务端商品校验、条码冲突检查及事务型商品编号分配。
- 原厂条形码扫码查询与未录入商品条码预填；
- 商品字段历史建议、单位快捷选择与连续录入。
- Product + Variant 多规格模型、规格汇总列表与规格条码定位。
- 多商品销售购物车、赠品、云端共享挂单与整单请求幂等；
- `sale_orders` 订单主记录、`sales` SKU 明细及整单事务扣库存。
- 按 Variant 入库、人工增减、盘点、低库存标记和库存流水查询。
- 销售记录与详情、首页今日经营数据及今日/本周/本月/自定义范围聚合统计。

## 本地配置

在 `miniprogram/envList.js` 中填写云开发环境 ID。数据库集合与权限、白名单数据和云函数部署需在微信开发者工具中完成。

商品编号使用 `settings/productCode` 计数器文档。首次部署 Phase 2 时需创建 `settings` 集合，并创建 `_id` 为 `productCode`、`value` 为 `0` 的文档。

Phase 3.5 起，`products` 只保存公共信息，规格、价格、库存和条码统一保存在 `product_variants`。项目尚未投入生产时，建议清空旧测试商品后按新模型重新录入，不长期兼容旧扁平模型。

销售与库存阶段需要创建 `sales`、`sale_orders`、`pending_sale_orders` 和 `inventory_logs` 集合，均禁止小程序客户端直接写入。新的高频销售流程通过 `checkoutSale` 一次提交整张订单；旧版 `saleProduct` 仅用于兼容已有单商品记录。

完整的集合、索引和云函数部署清单以 `开发文档.md` 为唯一基线。本地回归检查可执行 `tests` 目录中的全部 `*.test.js`。
